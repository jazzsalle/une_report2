# CC-250 증거 — SOP 캔버스·검증·검토·승인

- 항목: CC-250 (UNE-SOP-003~009)
- 결정 정본: **ADR-39** (D1~D11, 수용 한계 10)
- 마이그레이션: `0035_sop_review_approval_and_locked_versions.sql`
- 작성: 2026-08-10

## 1. 무엇이 동작하는가

```
POST /sops                        SOP 정의 생성        (SOP_EDIT, 201)
GET  /sops                        목록                 (SOP_READ, 200)
GET  /sops/{id}?versionId=        그래프 조회          (SOP_READ, 200)
POST /sops/{id}/versions          Draft 버전 저장      (SOP_EDIT, 201)
POST /sops/{id}/validate          DAG·임무·분기 검증   (SOP_EDIT, 200)

```

CC-240이 만든 DRAFT 그래프를 사람이 고치고 확정한다. provider를 부르지 않는다.

## 3. 착수 시점 상태

- `sop.status`·`sop_version.status`가 `('DRAFT')` 하나였다(0032가 예고한 확장).
- LOCKED 불변 트리거가 없었다.
- **`sop_validation`에 RLS 정책이 없었다 — 네 번째다.**
- 설계 10이 이름을 쓰는 `review_request`·`approval`이 **존재하지 않았다.**
- 일곱 오퍼레이션의 응답 스키마가 전부 `SopRun` 자리표시자였다(실행 리소스인데
  캔버스·검토·승인의 응답으로 적혀 있었다 — CC-220의 `GenericResponse`와 같은 유형).

## 4. 판단한 것

### 4.1 `review_request`/`approval`을 도메인 전용으로 만들었다 (ADR-39 D1)

설계 이름은 세 도메인 공용처럼 보이지만 컬럼 수준 설계가 없다. **공용을 버린
이유는 실제 사고다** — `generation_job`의 공용성이 CC-240에서 권한 경계를 뚫었다.
전용 테이블은 FK를 걸 수 있고 RLS가 부모 조인 하나로 끝난다. 되돌리기 비용도
비대칭이다(B→A는 UNION 뷰, A→B는 append-only 이력 분할).

이 판단은 fable과 상의해 결정했다.

### 4.2 승인 시점 해시를 감사 행에 동결한다

버전 FK만으로는 부족하다 — 버전이 가리키는 그래프가 바뀌면 승인의 대상이
조용히 달라진다. 그래서 D3(그래프까지 불변)이 함께 있다.

### 4.3 저장을 막는 것과 검증 보고로 넘기는 것을 갈랐다

400으로 막는 것은 **저장 자체가 불가능한 것**뿐이다: 중복 키(23505), 없는 노드를
가리키는 간선(DB는 id로 잇는다), 자기 자신 간선, 컬럼 폭 초과 제목(22001).
시작 노드가 없다거나 순환한다거나 하는 것은 검증 보고의 몫이다 — 고치는 중에는
깨진 그래프를 저장할 수 있어야 한다.

### 4.4 RLS 누락을 절차로 막았다

네 번 반복된 사고다. 전수 조사로 **정책이 한 번도 걸린 적 없는 테이블 18개**를
확인하고 목록을 테스트에 고정했다. 정책 없는 테이블이 새로 생기면
`rls-coverage.test.ts`가 먼저 빨개진다. 목록은 줄어들기만 할 수 있다.

## 5. 증명한 규칙

- **한 흐름이 이어진다.** 생성 → 저장 → 검증(PASS) → 검토 → 승인 → SOP APPROVED +
  버전 LOCKED + 검토 요청 해소 + 승인 기록(해시 동결).
- **저장은 새 버전이다.** 두 번 저장하면 버전이 둘이고 이전 그래프가 그대로 남는다.
- **낙관적 동시성.** 낡은 base로 저장하면 409이고 현재 버전 포인터가 바뀌지 않는다.
- **검토 중·승인 후 편집 불가.** 412.
- **승인 게이트.** 검증하지 않았거나 실패한 버전은 412이고 SOP는 IN_REVIEW로 남는다
  — 실행할 수 없는 절차가 "승인됨"으로 남지 않는다.
- **승인된 버전은 DB에서도 불변이다.** 버전 행·노드·간선·승인 기록 모두 42501.
  (버전만 막으면 그래프는 바뀌는데 해시는 그대로여서 승인한 것과 저장된 것이
  달라진다 — 그래서 자식까지 막는다.)
- **경계.** SOP_EDIT 없이 저장 403, 타 기관 조회 404(존재 은닉), 목록도 기관 안에서만.
- **저장할 수 없는 그래프는 400.** 23505/22001로 죽지 않는다.

## 6. 남은 조건

ADR-39 수용 한계 10개가 정본이다. 특히:

1. **반려·철회가 없다.** 검토자가 문제를 발견하면 승인하지 않는 것으로 끝나고,
   편집으로 돌아갈 방법이 지금은 없다 — 다음 항목의 첫 후보다.
2. **알림을 보내지 않는다.** 검토 요청은 DB 행일 뿐 아무에게도 가지 않는다(CC-270).
3. **검토자별 개별 응답이 없다.** 승인 게이트는 권한이지 지정 검토자 신원이 아니다.
4. **18개 테이블이 여전히 정책 없이 열려 있다.** 가드를 세웠을 뿐이고, 각 항목이
   자기 테이블을 열 때 함께 닫아야 한다.
