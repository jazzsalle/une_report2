# 요약

4차년도 POC의 상황일지 도구는 안전한국훈련 한 가지 용도에 맞춘 9장의 화면이었다. 3차년도 연구항목(매뉴얼·재난상황정보 연계, 상황일지 템플릿 정의, 현황·대응정보 시각화, 미리보기·출력, 다양한 형식 내보내기, 복구계획서·대응활동 평가 지원)에 대응하려면 이 도구를 위기관리·현장조치 매뉴얼을 쓰는 재난담당 공무원의 범용 도구로 다시 세워야 했다. 사용자 기관의 매뉴얼·보고서 샘플이 없었기 때문에 유니(UNE) 지식베이스 20,675건에서 위기관리 표준매뉴얼·실무매뉴얼·현장조치 행동매뉴얼·법령·안전한국훈련 가이드북을 검색해 구조를 분석했다. 분석에서 "조치목록 카드 7개 필드", "13개 협업기능", "위기경보와 비상단계는 다른 축", "법정 상황보고 체계와 제1호서식 항목", "훈련만의 요소는 시나리오·훈련 메시지·기대행동·평가뿐"이라는 다섯 가지 뼈대를 찾았고, 이를 근거로 상황 모델·매뉴얼 지식화·보고서 센터의 필요요소를 도출해 2026년 8월 22일~23일 이틀 동안 여섯 개의 PR(#42~#47)로 구현했다. 결과는 아래 표와 같다.

# 기(起) — 출발점과 문제

## 1. 4차년도 POC의 상황일지가 멈춰 있던 자리

4차년도에 만든 상황일지 생성 도구는 기획 화면 9장(훈련상황 생성 → 유니 SOP 생성·캔버스 편집 → 임무 전파 → 모바일 수신확인·완료보고 → 전자상황판 → 상황일지 → HWPX)을 그대로 구현한 것이었다. 동작은 했지만 다음 네 가지가 "안전한국훈련 한 번"에만 맞춰져 있었다.

- 산출물이 훈련 결과 기록 양식 1종(훈련 개요·최초 상황·시간대별 주요 상황·SOP 임무 수행·전파/수신·현장 조치·미완료·종합 의견)뿐이었다. 실제 재난에서 법으로 요구되는 최초·중간·최종 보고는 만들 수 없었다.
- 조직이 부서 6개(상황총괄반·현장통제반·시설복구반·주민대피지원반·유관기관협력반·안전총괄과)로 코드 안에 고정돼 있어 다른 기관이 쓸 수 없었다.
- SOP는 유니가 질의응답으로 만들어 주는 8~12개 임무였고, 기관의 매뉴얼에 적힌 조치와 연결되지 않았다. 근거가 "검색된 문장"에 머물렀다.
- 상황의 상태가 "상황단계" 문자열 하나였다. 위기경보(관심·주의·경계·심각)와 대책본부 비상단계(비상 1·2·3단계)가 다른 축이라는 점, 그 결정이 상황판단회의에서 내려진다는 점이 모델에 없었다.

## 2. 3차년도 연구항목이 요구한 것

연구 책임자가 정리한 3차년도 연구항목은 다음과 같다. 이 보고서의 모든 산출물은 이 항목에 대응된다(13절 대응표).

## 3. 방향 결정과 제약

2026년 8월 23일 토론에서 "1차 타깃은 안전한국훈련이지만, 위기관리 매뉴얼과 현장조치 매뉴얼을 활용하는 재난담당 공무원이 실제 상황에서도 쓰는 범용 도구로 만든다"고 정했다. 훈련과 실제를 따로 만들지 않고 **같은 화면에서 모드(실제상황·안전한국훈련·도상훈련)로 구분**하되, 훈련용 SOP를 실제용으로 "승격"하는 기능은 두지 않기로 했다.

제약은 분명했다. 사용자 기관의 매뉴얼과 상황보고서 샘플이 없었다. 그래서 분석 원천을 유니 지식베이스로 정하고, 거기에 올라 있는 다른 지자체·기관의 매뉴얼을 "기준 샘플"로 삼았다.

# 승(承) — 무엇을 분석했나

## 4. 분석 방법

유니 RAG의 검색 기능(MCP 도구 search_knowledge, 서버에서는 REST 검색 — 둘 다 같은 512자 청크와 출처 문서명·유사도를 돌려준다)으로 지식베이스를 질의했다. 구조 파악용 질의 19종(목차 구성, 단계 발령 기준, 부서별 임무, 보고 체계, 현장 점검 항목, 대책본부 구성, 훈련 시나리오, 감염병 등 다른 재난유형과의 공통 구조, 상황보고서 양식 등)을 순차로 돌리고, 그 결과에서 드러난 조치목록 카드를 정규식으로 구조화하는 추출 질의를 매뉴얼당 13회 실행했다. 지식베이스에 있는 문서는 세 계층이 모두 갖춰져 있었다.

| 계층 | 확인된 문서 | 분석에 쓴 것 |
|---|---|---|
| 위기관리 표준매뉴얼(재난관리주관기관) | 풍수해(행안부 2020), 감염병, 지진, 산불, 다중밀집시설 대형화재, 해양 선박사고 | 위기경보 판단기준, 범정부 체계, 13개 협업기능 |
| 위기대응 실무매뉴얼(부처·기관) | 풍수해(환경부·문화재청·국가유산청·학교시설), 감염병, 산사태, 공연장·경기장 | 위기경보 수준별 조치, 부서별 임무, 보고 서식 |

부족한 것은 "상황보고서의 실제 HWP 원본"(법령 별지 서식은 본문 텍스트만 있음)과 사용자 기관 매뉴얼이었다. 전자는 영천시 매뉴얼 부록의 제1호서식 항목을 기준으로 삼아 메웠다.

## 5. 분석 결과 — 도구가 따라야 할 다섯 가지 뼈대

### 5.1 현장조치 행동매뉴얼은 기관이 달라도 같은 구조다

영천시·부산시 북구·전북교육청의 매뉴얼이 같은 장 구성을 따른다. Ⅰ 일반사항(위기경보 관심 Blue·주의 Yellow·경계 Orange·심각 Red) — Ⅱ 대응체계(지역재난안전대책본부 구성, 실무반 = 13개 협업기능, 비상연락망, 상황실) — Ⅲ 대응절차(징후감지 → 초기대응 → 비상대응[지대본 비상 1 / 2·3단계] → 수습복구, 단계마다 상황·대응지침·위기경보 표) — Ⅳ 단계별 행동요령(대응지침, 지휘부 임무, **조치목록 카드**) — Ⅴ 부록(상황보고서·상황판단회의·자원동원 현황 서식, 비상연락망).

함의: 도구의 "대응 단계"는 이 절차(징후감지·초기대응·비상1·비상2·3·수습복구)를 그대로 쓰면 되고, SOP의 원천은 Ⅳ장 조치목록 카드다.

### 5.2 조치목록 카드 = SOP 임무의 원형

매뉴얼의 모든 조치는 프로세스 코드로 묶여 있다. 예를 들어 ①-1은 위기징후 관리(①-1-1 감시, ①-1-2 접수·파악, ①-1-3 보고·전파, ①-1-5 상황판단회의), ①-2는 대응조치(①-2-1 긴급대응, ①-2-9 지역자율방재단 가동), ①-3은 상황실 가동(①-3-1 재난상황 접수·파악, ①-3-2 전파·보고), ⑪-1-3은 대피명령 발령, ⑬-1-1은 재난방송·홍보다. 카드 한 장의 필드는 **코드번호 · 조치목록 · 조치내용 · 주관부서 · ⓢ지원부서 · ⓒ협업기관 · 연계코드** 7개이고, 카드 아래에 세부 행동 항목이 따라온다.

함의: POC의 SOP 임무(프로세스·판단·전파·현장확인·자동기록)는 이 카드의 부분집합이다. 임무에 코드·협업기능·주관/지원/협업·연계코드·원문 출처를 붙이면 매뉴얼과 1:1로 대응되고, "AI가 만든 임무"가 "매뉴얼 ①-3-2 조치"로 바뀐다.

### 5.3 13개 협업기능이 실무반 편성의 표준이다

재난상황관리 · 긴급생활안정지원 · 긴급통신지원 · 시설피해 응급복구 · 에너지 공급 피해시설 복구 · 재난관리자원 지원 · 교통대책 · 의료·방역 · 재난현장 환경정비 · 자원봉사 지원·관리 · 사회질서 유지·주민대피 · 수색·구조·구급 · 재난수습 홍보. 영천시 매뉴얼의 코드 원문자(①~⑬)가 바로 이 번호다.

함의: 부서 6개를 코드에 고정하는 대신 **협업기능 → 실무반 → 부서 → 담당자** 순으로 기관마다 등록하게 해야 범용이 된다.

### 5.4 위기경보와 비상단계는 다른 축이고, 결정은 상황판단회의에서 내려진다

위기경보(관심·주의·경계·심각)는 재난관리주관기관이 상황판단회의에서 심각성·시급성·확대가능성 등을 종합해 결정한다. 비상단계(지대본 비상 1 / 2 / 3단계)는 대책본부 근무 규모이며 풍수해는 기상특보와 연동된다(예비특보·주의보 → 초기대응, 경보 → 비상 1, 광역 경보·피해 → 비상 2·3). 상황판단회의 개최 시기와 준비(3시간 전 개최 보고, 참석기관 통보)도 단계별로 규정돼 있다.

함의: 상황 모델에는 위기경보 이력, 비상단계 이력, 상황판단회의(결정 이벤트) 세 가지가 있어야 하고, 기상특보는 단계 전환의 근거 자료로 붙어야 한다.

### 5.5 상황전파는 "담당자 문자"가 아니라 대상군 × 채널이다

전파 대상은 지대본 협업부서·읍면동·협업기관(소방·경찰·KT·한전·가스)·사전 지정 위험지역 주민·대국민이고, 수단은 CBS 긴급재난문자(상황판단회의 후 결정)·TV 자막방송·민방위 경보·자동우량경보·마을앰프·문자·공문 등이다.

함의: POC는 내부 임무 전파만 다루므로, 기관 설정에 전파 대상군(내부·유관기관·주민·대국민)을 등록하고 실제 송출은 범위 밖으로 둔다.

### 5.6 법정 상황보고 체계와 상황보고서 양식 항목

재난 및 안전관리 기본법 시행규칙은 **최초 보고**(주요 재난 발생 시 지체 없이, 가장 빠른 방법) — **중간 보고**(수습기간 중 수시, 별지 제1호서식) — **최종 보고**(수습 종료 후 종합) — 수시 보고(선 유·무선 후 문서) — 정기 일일 보고(1일 4회 09·13·18·22시, 재난상황총괄표·응급복구·응급구호)를 정한다. 보고 대상은 내부(시장·부시장·국장) / 상급기관(도 재난관리과) / 중앙(행안부 중앙재난안전상황실)이다.

매뉴얼 부록과 법령 서식에서 공통으로 뽑은 상황보고서 항목은 다음과 같다.

| 구역 | 항목 |
|---|---|
| 머리 | 보고 시각("○월 ○일 ○○:○○ 현재"), 보고자(소속·직책·성명·연락처), 제목, 배부처(보고 라인) |
| 1 발생 개요 | 접수시간·출처, 발생일시·장소·원인, 재난기간·지역 |
| 2 피해 상황 | 인명피해, 시설(물적)피해 표(시설명·피해내용·복구대책·소요액), 이재민 |
| 3 대응 현황 | 시간대별 주요 조치사항, 자원동원(배치) 현황 표(기관·책임자·인원·장비·배치장소·투입/철수), 주민대피, 교통두절 |
| 4~7 | 본부장 요청사항 처리, 원인·재발방지 대책(중간·최종), 향후 계획, 참고사항(언론 동향) |

함의: POC의 상황일지 8절은 "훈련 결과 기록" 양식이다. 실제 상황의 산출물은 즉보·중간·최종 보고이며, 시간대별 조치·자원동원·피해 표가 핵심이다. 두 문서는 **같은 이벤트 원장**에서 투영해야 한다.

### 5.7 훈련만의 요소는 네 가지뿐이다 — 범용화의 근거

안전한국훈련 가이드북의 고유 요소는 통합 훈련시나리오(시간전개·상황·피해·기능별 임무), 훈련 메시지(번호·시각·발신·수신·방법·내용·기대 행동), 부서임무카드, 평가(사전·현장 12지표·사후)다. 대책본부 구성·전파·보고·상황일지는 실제 상황과 같다.

함의: 훈련 모드 = 실제 상황 모드 + 시나리오·훈련 메시지·기대행동·평가. 따라서 한 엔진으로 두 모드를 돌릴 수 있다.

### 9.6 재난대응 활동 평가서 (연구항목 4)

- 분석: 안전한국훈련 가이드북의 현장 평가 12지표(상황전파 체계·비상기구 가동 충실성 등)와 사후 평가(문제점 도출·개선계획), 5.6의 시간대별 조치, 그리고 도구가 이미 쌓고 있는 이벤트 원장(전파·수신확인·완료 보고·지연·회의·경보 변경·특보 기록)
- 도출한 필요요소: 기록에서 **자동으로 계산되는 지표**와 평가자가 적는 의견 칸의 분리. 지표 11개 — 최초 상황 → 첫 임무 전파(분), 임무 전파 건수/전체, 수신 확인률, 평균 수신 확인 소요, 임무 완료율, 기한 내 완료율, 지연·미완료·지원요청 건수, 현장 완료 보고 건수, 상황판단회의 횟수, 위기경보·단계 변경 횟수, 기상특보 기록 건수
- 구현: 평가서 템플릿 7절(평가 개요 · 대응 지표 · 단계별 경과 · 기대행동·임무 평가 · 전파·수신 · 회의·의사결정 · 문제점 및 개선과제). 대응 지표 표는 값과 산출 근거를 함께 적고 평가 열을 비운다. 실측(훈련 TP4wm_UNV2): 첫 전파 4분, 전파 5/5, 수신 확인률 20%, 평균 수신 소요 21분, 완료율 0%, 지연 5건.

### 9.7 내보내기·미리보기 (연구항목 2-4·2-5)

- 분석: 기존 HWPX 내보내기(템플릿 견본 구간 교체)와 rhwp의 쪽 단위 SVG 렌더가 원본과 같게 나온다는 앞선 실측, 6의 PDF 실측
- 필요요소: HWPX 템플릿 선택 · PDF(한글 설치 없이) · DOCX · 내보내기 전에도 보이는 미리보기 · 최근 파일 재다운로드
- 구현: 세 형식 버튼과 미리보기 모달. PDF는 HWPX → 쪽 SVG → A4 HTML → 헤드리스 브라우저 인쇄(Chrome → Edge 대체, 둘 다 없으면 설치 안내 창). DOCX는 제목·불릿·표·문단을 변환하고 템플릿의 본문 글꼴·크기를 근사한다.

## 10. 사용성 원칙 — 시간이 생명인 화면

사용자가 "상황이 전개되면 시간이 생명이니 사용성 문제로 피해를 줘선 안 된다"고 정한 뒤, 구현 중 보이는 문제를 그때그때 제안하고 결정받아 반영했다.

- 순서도 노드가 작아 임무가 안 보임 → 카드형 노드(제목 2줄·담당·배지), 마우스를 올리면 확장 카드, 표 보기
- 매뉴얼 템플릿 SOP가 44개 임무 한 줄로 길어짐 → **현재 단계만 보기**(현재 대응 단계 구간만 펼치고 나머지 단계는 막대로 접음, 상황판단회의로 단계가 바뀌면 자동으로 열리고 그 위치로 이동)
- 부서 간 흐름이 안 보임 → 협업기능별 스윔레인, 띠를 가로지르는 선은 꺾은선
- 긴 순서도 → 줌/팬·맞춤, 단계 구분선

# 부록

## 용어

- 위기경보: 재난의 심각성에 따른 관심(파랑)·주의(노랑)·경계(주황)·심각(빨강) 4단계. 상황판단회의에서 결정한다.
- 대응(비상) 단계: 대책본부가 얼마나 크게 움직이는가. 징후감지 → 초기대응 → 비상 1단계 → 비상 2·3단계 → 수습복구.
- 협업기능: 재난 대응을 13가지 기능(재난상황관리, 긴급생활안정지원, 교통대책 …)으로 나눈 표준. 실무반은 이 기능에 따라 편성된다.
- 조치목록 카드: 매뉴얼에서 "누가(주관·지원·협업) 무엇을(조치내용) 어느 단계에" 하는지 적은 한 장. 코드(①-2-8)로 서로 연결된다.
- 투영 블록: 이벤트·임무·회의 기록을 보고서의 표로 자동으로 옮겨 적는 규칙. 사람이 쓴 절(서술)과 구분된다.
- 스윔레인: 수영장 레인처럼 세로 띠를 협업기능(또는 부서)별로 두고 각 임무를 담당 띠에 놓는 보기. 순서도가 "무엇을 어떤 순서로"라면 스윔레인은 "누가 무엇을"이다.
- 이벤트 원장: 상황에서 일어난 모든 일(최초 상황, 전파, 수신확인, 완료 보고, 지연, 회의, 경보 변경, 특보)을 시간순으로 지우지 않고 쌓은 기록. 모든 보고서의 단일 원천이다.
