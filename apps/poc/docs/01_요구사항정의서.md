- 버전: v1.0 (2026-08-19)
- 목적: **동작하는 POC**를 만들어 개발팀에 인계한다. 보안·암호화·멀티테넌트·감사·멱등성은 범위 밖.

## 2. 재난안전계획서 생성 도구 (PLAN)

2차년도 화면설계서(V0.2.6)의 흐름을 따른다: **문서 저장 → 기준정보 준비 → 목차 생성/편집 → 초안 생성(목차별 진행 확인) → 편집 → 내보내기**.

화면 스타일(2026-08-21): KRDS v1.0.0 토큰 기반 업무시스템형 골격 — 상단 헤더+GNB(`AppHeader`), 문서 작업 화면은 단계 파이프라인 칩 + 우측 "생성 기준"·"연동 상태" 레일. 시안은 `design_handoff_krds_uiux/poc-plan/`, 구현은 `apps/poc/web/src/krds.{css,tsx}`. 상황일지(/sit)·홈·모바일도 같은 날 같은 스타일로 맞춤 — 상황일지는 공통 부품 `ui.tsx`를 KRDS 클래스로 갈아끼우는 방식(셸은 상단 헤더 + LNB 띠 + 현재 훈련상황 띠).

### PLAN-01 템플릿 스타일 분석 모듈 (신규, 사용자 요구 ②)

| 항목 | 내용 |
|---|---|
| 입력 | HWPX 파일 업로드 (`templete/*.hwpx` 6종으로 검증) |
| 처리 | rhwp WASM(`@rhwp/core`)으로 파싱 → 스타일 목록(`getStyleList`), 개요번호 형식(`getNumberingList` → `levelFormats` 예: `^1.`,`^2.`,`^3)`), 문단별 글꼴·크기·굵기·정렬·들여쓰기(`getCharPropertiesAt`, `getParaPropertiesAt`), 문단 텍스트 |
| 출력 | **템플릿 프로파일 JSON**: `{ templateId, name, styles[{id,name}], numbering[{id,levelFormats}], levels[{level, styleId, styleName, bullet, fontFamily, fontSizePt, bold, indent}], sampleParagraphs[] }` |
| 활용 | (a) LLM 프롬프트에 "1수준 □ 16pt 굵게, 2수준 ㅇ 15pt, 3수준 - 15pt, 4수준 * 12pt" 규칙 주입 (b) HWPX 내보내기 때 heading level → `styleId` `applyStyle` (c) 웹 렌더 CSS에 글꼴·크기 반영 |
| 검증 | `문서 템플릿_01.hwpx`에서 26 스타일·개요 4수준·글자크기 16/15/15/12pt 인식 (실측 2026-08-19) |

## 3. 상황일지 생성 도구 (SIT) — 4차년도 안전한국훈련용

## 4. 계획서 ↔ 상황일지 연동 (LINK) — 사용자 요구 "아이디어"

| # | 기능 | 방향 |
|---|---|---|
| LINK-01 | **계획서에서 훈련 시작**: 계획서의 SOP/비상연락망/대응절차 절을 뽑아 훈련상황 생성 화면의 시나리오·참조 데이터에 자동 채움. SOP 생성 프롬프트에 "이 계획서의 절차를 따르라"고 주입 | 계획서 → 훈련 |
| LINK-02 | **훈련 결과를 계획서로 환류**: 훈련 종료 시 지연·미완료 임무와 개선 필요사항을 계획서의 "개선사항/보완계획" 절 초안으로 역주입(새 문단, "훈련 환류" 표시) | 훈련 → 계획서 |
| LINK-03 | 계획서 문서 목록에 "이 계획서로 훈련한 이력" 링크, 훈련상황에 "근거 계획서" 링크 | 양방향 탐색 |

원칙: **계획서(예방·대비) → 훈련(대응 연습) → 계획서 개정**의 순환이 한 화면 흐름 안에서 이어진다.
