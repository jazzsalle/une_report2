## 1. 매뉴얼 구조 — 도구가 따라야 할 뼈대

### 1.1 현장조치 행동매뉴얼의 공통 구조 (영천·부산북구·전북교육청이 같은 양식)
```
Ⅰ 일반사항      목적 · 적용범위 · 위기형태 · 위기경보(관심 Blue / 주의 Yellow / 경계 Orange / 심각 Red)
Ⅱ 대응체계      지역재난안전대책본부(지대본) 구성 · 실무반(13개 협업기능) · 비상연락망 · 상황실
Ⅲ 대응절차      재난대응 절차도 · 재난대응 단계(징후감지 → 초기대응 → 비상대응[지대본 비상 1 / 2·3단계] → 수습복구)
                각 단계마다 [상황 · 대응지침 · 위기경보] 표
Ⅳ 단계별 행동요령  단계마다  가. 대응지침  나. 지휘부 임무와 역할(시장/부시장/국장 — [초동지시][상황판단회의 주재][필요시]…)
                            다. 조치목록 카드  ← 핵심
Ⅴ 부록          상황보고서·상황판단회의·자원동원 현황·자원봉사 보고 등 서식, 비상연락망
```
("(영천)풍수해 현장조치 행동매뉴얼", "풍수해_3행동매뉴얼_부산시북구(2023)", "교육시설_3행동매뉴얼_전북교육청(2025)")

### 1.2 조치목록 카드 = SOP 노드의 원형
매뉴얼의 모든 조치는 **프로세스 코드**로 묶여 있다.
```
[①-1] 위기징후 관리   [①-1-1] 감시  [①-1-2] 접수·파악  [①-1-3] 보고·전파  [①-1-4] 분석·평가  [①-1-5] 상황판단회의(위기평가회의)  [①-1-6] 위기(위험) 예보
[①-2] 대응조치       [①-2-1] 긴급대응 조치  [①-2-3] (필요시) 위험구역 설정  [①-2-4] 대책본부 운영 준비  [①-2-5] 유관기관 협조체계 점검 … [①-2-9] 지역자율방재단 가동
[①-3] 상황실 가동     [①-3-1] 재난상황 접수·파악  [①-3-2] 재난상황 전파·보고  [①-3-3] 필요 자원 파악·지원 요청
…  [⑪-1-3] 대피명령 발령   [⑬-1-1] 재난방송 및 홍보
```
카드 한 장의 필드: **코드번호 · 조치목록 · 조치내용 · 주관부서 · ⓢ지원부서 · ⓒ협업기관 · 연계코드**(예: 위기경보 발령 카드 → 연계 ①-2-1 긴급대응 조치, ⑬-1-1 재난방송 및 홍보). ("(영천)풍수해 현장조치 행동매뉴얼" Ⅳ장)

→ 지금 POC의 SOP 노드(`TASK/DECISION/DISPATCH/FIELD_CHECK/AUTO_LOG`)는 이 카드의 **부분집합**이다. 노드에 `code`(①-3-2), `coopFunction`(13개 협업기능 중 하나), `lead/support/partner`(주관/지원/협업), `linkedCodes`를 붙이면 매뉴얼과 1:1로 대응된다.

### 1.3 13개 협업기능 (실무반 편성의 표준)
재난상황관리 · 긴급생활안정지원 · 재난현장 환경정비 · 긴급통신지원 · 시설피해 응급복구 · 에너지 공급 · 피해시설 복구 · 재난수습 홍보 · 재난관리자원 지원 · 교통대책 · 의료·방역 · 자원봉사 지원·관리 · 사회질서 유지 / 수색·구조·구급 ("풍수해_1표준매뉴얼_행안부(2020)", "3. 기초현황 조사"). 지자체는 이를 실무반(상황총괄반·시민소통반·행정지원반·대외협력반·의료지원반·자원봉사지원반·공보지원반 …)으로 편성한다.

→ 지금 POC의 부서 6개(상황총괄반·현장통제반·시설복구반·주민대피지원반·유관기관협력반·안전총괄과)는 이 중 일부를 임의로 고른 것. **조직은 "협업기능 → 실무반 → 부서 → 담당자"로 기관마다 등록**해야 범용이 된다.

### 1.4 위기경보와 비상단계는 다른 축
- **위기경보**(관심·주의·경계·심각): 재난관리주관기관이 **상황판단회의**에서 결정. 판단기준은 표준매뉴얼에 있으나 "심각성·시급성·확대가능성·전개속도·지속시간·파급효과·여론·대응능력을 종합"해 탄력 적용, 지역 단위 발령 가능, 대국민 경보는 경계·심각만. ("풍수해_1표준매뉴얼_행안부(2020)", "다중밀집시설 대형화재 표준매뉴얼")
- **비상단계**(지대본 비상 1 / 2 / 3단계, 중대본 1~3단계): 대책본부 근무 규모. 풍수해는 태풍정보·호우 예비특보(징후감지) → 예비특보·주의보(초기대응) → 경보(비상 1) → 광역 경보·피해(비상 2·3) 식으로 기상특보와 연동된다. ("GB-제3장 기초현황 조사" 재난대응 절차 표)
- **상황판단회의** 개최 시기도 단계별로 규정(예비특보부터 필요시 / 일부 지역 경보 / 광역 경보), 준비 역할(3시간 전 개최 보고, 참석기관 통보) ("교육시설_3행동매뉴얼_전남교육청", "●부산시 풍수해 재난 현장조치 행동매뉴얼")

→ 도구의 상황 모델에 **위기경보 이력 + 비상단계 이력 + 상황판단회의(결정 이벤트)** 세 가지가 필요하다. 지금은 `alertLevel` 문자열 하나.

### 1.5 상황전파 수단과 대상
전파 시기(위기경보 발령·재난 발생(예측) 상황), 대상(지대본 협업부서·읍면동·협업기관: 소방·경찰·KT·한전·가스), 수단: **CBS 긴급재난문자(상황판단회의 후 결정)** · TV 자막방송(DITS) · 민방위 경보시설 · 자동우량경보 · 전광판 · 마을앰프·가두방송 · 사전 지정 위험지역 주민 연락처 DB · 유·무선·SMS·공문·NDMS. ("(영천)풍수해 현장조치 행동매뉴얼" 상황전파 카드, "해양 선박사고 표준매뉴얼")

→ 전파는 "담당자 SMS" 하나가 아니라 **대상군(내부 실무반 / 유관기관 / 사전지정 주민 / 대국민)별 채널**이다. POC는 내부 임무 전파만 다룬다 — 범용화 시 대상군과 채널 어댑터를 모델에 두되, 실제 송출은 범위 밖으로 유지.

### 1.7 상황보고서 양식 (매뉴얼 부록·법령 서식에서 공통으로 뽑은 항목)

- **2 피해 상황**: 인명피해, 시설(물적)피해 표(기관·행정구역·시설명·피해내용·복구대책·소요액), 이재민
- **3 대응 현황**: **시간대별 주요 조치사항**(00:00 …), **자원동원(배치) 현황** 표(기관·책임자·인원·장비·배치장소·투입/철수시간), 주민대피 현황, 교통두절 상황
- **4 본부장 요청사항 처리내용** / **5 원인 및 재발방지 대책**(중간·최종보고에만) / **6 향후 계획** / **7 참고사항**(언론 동향·여론)
- 첨부: 피해 현황 사진
("(영천)풍수해 현장조치 행동매뉴얼 제1호서식", "●부산시 풍수해 재난 현장조치 행동매뉴얼", "공연장 경기장 안전사고 실무매뉴얼 부록", "교육시설_3행동매뉴얼_전남교육청", "지진재난 위기대응 실무매뉴얼")

→ 지금 POC의 상황일지 8절(훈련 개요·최초 상황·시간대별 주요 상황·SOP 임무 수행 내역·전파/수신 내역·현장 조치 결과·미완료/개선·종합 의견)은 **훈련 결과 기록** 양식이다. 실제 상황의 산출물은 위 **상황보고서(즉보/1보/2보/최종)** 이고, 3절(시간대별)·자원동원·피해 표가 핵심이다. 둘은 같은 이벤트 원장에서 **다른 투영**으로 만든다.

### 1.8 현장 점검 항목 (모바일 체크리스트의 원천)
평시·초기대응 조치목록에 현장 확인 항목이 구체적으로 있다: 침수방지 배수로 점검, 붕괴우려지 순찰, 급경사지·산사태 취약지역 관리, 지하차도·하상도로 등 침수우려 도로 통제 준비(인력·자재·장비), 현장출동 장비·수방자재 가동 점검, 비상연락망 정비, 취약시설 긴급 전수점검·사전통제(도로·하천변·둔치주차장·탐방로), 복명서 제출. ("●부산시 풍수해 재난 현장조치 행동매뉴얼", "2023 재해연보", "E-SOP 컨설팅 보고서": 현장 순찰 점검 1회/1시간, 옥상·옥외 배수로·배수구, 지하배수펌프, 차수판)

→ 모바일 "수행 지시사항"은 하드코딩 3줄이 아니라 **조치목록 카드의 조치내용 + 시설 유형별 점검 항목**에서 생성한다.

### 1.9 안전한국훈련의 고유 요소 (훈련 모드만의 것)
- 훈련 유형: **토론기반**(상황판단회의 훈련·비상대책기구 운영훈련·문제해결형 의사결정훈련) / **실행기반**(기능훈련·실제훈련·통합연계훈련·공동주관훈련)
- 설계 문서: **통합 훈련시나리오**(시간전개[누적/실제]·상황·피해·임무와 역할[13개 기능별]·주요 쟁점; 단계 징후감시→초기대응→초동대응→수습복구), **훈련 메시지**(번호·시간·발신·수신·방법·내용·기대 행동목록 — "누가 보내고 누가 기대 행동을 취하는지", 시간을 부여), **부서임무카드**(단계별 조치목록·조치내용), 훈련 실행계획서, 불시훈련 계획
- 평가: 사전(매뉴얼 적절성·기획팀) / 현장(기관장 참여·협업·**상황전파 체계 및 비상기구 가동 충실성** 12지표 46점) / 사후(문제점 도출·개선계획) ("2023년 안전한국훈련 가이드북(훈련담당자용)", "2019 안전한국훈련 우수기관 선정결과")

→ 훈련 모드 = 실제 상황 모드 + **시나리오(시간전개) · 훈련 메시지(상황 부여 이벤트) · 기대 행동(평가 기준) · 훈련 평가서/결과보고서**. 나머지(대책본부·전파·보고·상황일지)는 실제 상황과 같은 엔진을 쓴다. 이것이 "범용화"의 근거다.

## 2. 범용 데이터 모델 제안

```
Org          기관 프로필: 기관명·지대본 구성·실무반(협업기능 매핑)·부서·담당자·연락처·보고 라인(내부/상급/중앙)·전파 대상군(읍면동·유관기관·사전지정 주민)
Manual       등록 매뉴얼: 계층(표준/실무/현장조치)·재난유형·기관·버전·유니 doc_id·추출 상태
ActionCard   조치목록 카드(매뉴얼에서 추출): code ①-3-2 · stage(징후감지/초기대응/비상1/비상2·3/수습복구) · title · content · coopFunction · lead/support/partner · linkedCodes · checklist[] · sourceRef(문서·쪽)
SopTemplate  재난유형×기관별 표준 SOP = ActionCard들을 노드·간선으로 엮은 그래프(판단 분기 포함). 매뉴얼 버전에 묶임
Incident     상황: mode(실제/안전한국훈련/도상훈련) · 재난유형 · 발생정보 · alertHistory[{level, decidedAt, meeting}] · stageHistory[{stage, at}] · warningsSnapshot(기상특보) · linkedPlanId · status
Sop          Incident에 적용된 SOP 인스턴스(템플릿 + 상황 보정), 버전
Task         (현행 유지) + code · coopFunction · channelTargets[] · checklist[{text, done, at}] · photos[] · location
Event        (현행 유지, 삭제 없음) kind에 '위기경보 변경' '비상단계 변경' '상황판단회의' '기상특보' 추가 · sourceRef
Meeting      상황판단회의: 시각·주재·참석·안건·결정(경보 수준·비상단계·대피명령·CBS 발송 여부) → Event 기록
Report       보고서: type(상황일지/즉보/1보/2보/최종/일일정기/훈련결과) · sections(fact/narrative) · version · reviewed · 배부처 · HWPX 템플릿
Dissemination 전파 건: 대상군(내부 실무반/유관기관/사전지정 주민/대국민) · 채널(내부알림·SMS·알림톡·CBS·DITS·방송) · 메시지 · 수신 레코드(현행 Task 수신/보고 구조 재사용)
Scenario     (훈련 모드) 시간전개 · 상황 · 피해 · 기능별 임무 · 쟁점;  Message(훈련 메시지: 시각·발신·수신·방법·내용·기대행동[ActionCard code]) → 시각 도달 시 Event/Task 자동 부여
Evaluation   (훈련 모드) 기대행동 대비 실제 이벤트 매칭 → 지표별 점수·개선계획
```
- 기존 `Exercise`는 `Incident(mode='안전한국훈련')`로 흡수. 기존 데이터는 마이그레이션(필드 추가)으로 유지.
- 파일 JSON 저장소(`store.ts`)는 유지하되 컬렉션이 늘어나므로 DB 이전 경계를 지킨다.

## 6. 결정이 필요한 것 (토론 안건)
1. **모드**: 한 화면에서 실제/훈련/도상 모드 전환(추천) vs 메뉴 분리
2. **기관 매뉴얼 입수**: 사용자 기관의 현장조치 행동매뉴얼·상황보고 양식(HWP) 샘플을 주면 조치카드 추출과 보고서 양식을 그 기관 기준으로 맞춘다. 없으면 영천시 매뉴얼을 기준 샘플로 쓴다.
3. **조직 데이터 위치**: 도구 안 기관 설정(추천) vs 계획서 비상연락망 절에서 추출
4. **보고서 우선순위**: 즉보·1보·2보·최종(법정) 먼저 vs 일일 정기보고 먼저
5. **전파 범위**: 내부 임무 전파 + 유관기관·주민·대국민은 "기록만"(추천) vs 실제 채널 연동 시도
6. **상황판단회의**를 독립 화면으로 둘지, 상황판 카드로 둘지
7. **인증·역할 최소 범위**: 역할(상황총괄/부서/현장/조회)만 두고 인증은 계속 범위 밖?
8. **1차 구현 범위**: 로드맵 ①②③까지를 1차로(추천) — 실제 상황에서 바로 쓰이는 "매뉴얼 기반 SOP + 법정 보고서"가 범용화의 가치이기 때문

## 부록 A. 현 POC 인벤토리에서 드러난 구멍 (탐색 결과 요약)
- SOP 노드의 채널·기록 규칙, 상황 생성 옵션이 **저장만 되고 서버 로직에 반영되지 않음**
- 모바일 사진·위치·체크리스트가 **문구뿐**(저장 없음); "자동 저장됨" 배지 하드코딩
- 상황일지 재생성이 **편집분을 덮어씀**(버전 없음); SOP 버전 목록 UI 없음
- 다중 수신자 전파 미지원(recipients[0]만), 전파 템플릿·변수 치환 클라이언트/서버 이중 정의
- 지연 판정이 폴링 의존(lazy), 사용자 6명 고정, 연계데이터·환경설정 정적 목업
